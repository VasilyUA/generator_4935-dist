# README

## 📌 Опис

Цей репозиторій містить декілька інструментів для генерації звітів на основі Excel файлів.  
Усі проєкти працюють за схожим принципом: беруть вхідні дані з папки `resources` і створюють результат у папці `output`.

---

# ⚙️ Загальний принцип роботи

Перед запуском для кожного проєкту необхідно:

1. Підготувати Excel файли
2. Покласти їх у папку resources
3. Перейти в папку проєкту (cd ...)
4. Запустити python index.py
5. Забрати результат у папці output

## 🔹 generator_br_and_report_for_money — структура

```
generator_br_and_report_for_money/
├── resources/                                ⚠️ немає в git — після клонування створюєте самі
│   ├── ОБЛІК.xlsx (або .xlsm)/
│   │   ├── аркуш "<ПОТОЧНИЙ МІСЯЦЬ>" (напр. "СЕРПЕНЬ") — ПІДРОЗДІЛ, ПОСАДА, звання фактичне, ПІБ, дати місяця, (необов.) ПІДСТАВИ
│   │   └── аркуш "ТВО" — Підрозділ, ПОСАДА, Start, End, ЗВАННЯ, ПІБ, ТВО
│   ├── ПРИДАНІ.xlsx                          ← необов'язково — приданий особовий склад
│   ├── data.json                             ← назва частини + ВСІ тексти БР/рапортів (зразок і пояснення кожного ключа — у розділі проєкту нижче)
│   ├── check/                                ← лише для "Звірка обліку": кілька ОБЛІК*.xlsx, які звіряються між собою
│   └── changes/                              ← лише для поправок за минулий місяць
│       ├── prev_MM_ОБЛІК.xlsx                ← як БУЛО за місяць MM (напр. prev_06_ОБЛІК.xlsx)
│       └── actual_MM_ОБЛІК.xlsx              ← як МАЄ БУТИ за той самий місяць
├── output/                                   ← ⚠️ повністю очищається перед кожною генерацією БР
│   ├── br/ , br_save/ , extractbr/ , logwar/ ← бойові розпорядження й витяги
│   └── *.docx                                ← рапорти на додаткову винагороду
└── constants.py                              ← див. таблицю нижче
```

▶️ Немає `resources/`? Створіть заготовку (кілька вигаданих рядків, показує точну структуру — заповніть, коли на неї подивитесь):

```bash
cd generator_br_and_report_for_money && python resources_example/generate_sample.py
```

Створює `resources/ОБЛІК.xlsx` (аркуш поточного місяця + порожній `ТВО`). `resources/data.json` — окремо, повний зразок нижче в розділі проєкту (готовий JSON-блок для копіювання).

#### 🔧 Основні змінні `constants.py`

| Змінна                                                                                           | За що відповідає                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MONTH`, `YEAR`                                                                                  | Обраний при запуску місяць/рік генерації — саме за ним шукаються колонки-дати в `ОБЛІК.xlsx`.                                                                                                |
| `MONEY_REPORT_CATEGORIES`                                                                        | Пункти рапорту на виплату (10к/30к/50к/70к/100к/170к) — текст пункту й підстави (накази/БР) для кожного. Новий пункт виплати додається лише сюди, без правок коду.                           |
| `COMMANDER_MONEY_REPORT_CATEGORIES`                                                              | Те саме, але для окремого рапорту командира/ТВО.                                                                                                                                             |
| `NUMBER_OF_DOCUMENTS_BRS_EVERY_DAY`                                                              | Номери щоденних бойових розпоряджень (по днях місяця).                                                                                                                                       |
| `NUMBER_OF_DOCUMENTS_BRS_EVERY_WEEK`                                                             | Номери щотижневих "ЗАВДАННЯ" (по тижнях).                                                                                                                                                    |
| `NUMBER_OF_DOCUMENTS_BRS_SAVE`                                                                   | Номери розпоряджень з безпеки застосування військ.                                                                                                                                           |
| `MONEY_REPORT_CHANGES_ORDER_REFERENCES`                                                          | Номери наказів, якими вносились зміни за **попередні** (не поточний) місяці — підставляються в "Прошу внести зміни в наказ №*** від***", щоб не лишати порожнє місце для ручного заповнення. |
| `BR_HIGHT_UNIT`, `MONEY_REPORT_GENERAL_REFERENCES_BN`, `MONEY_REPORT_GENERAL_REFERENCES_LOG_WAR` | Підстави від бригади (БР/БН/ЖБД), які підставляються автоматично й ігноруються при звірці рапорту з ОБЛІК.                                                                                   |
| `SHORT_UNIT_BATTALION`, `SHORT_UNIT_BRIGADE`, `FULL_UNIT_BUT`, `FULL_MILITARY_UNIT`              | Назва/скорочення частини — **не редагуються тут напряму**, читаються з `resources/data.json` (ключ `"unit"`), бо `resources/` не в git.                                                      |
| `PERSONEL_LIST_SHEET_NAME`                                                                       | Назва аркуша в `ОБЛІК.xlsx`, який зараз читається (= поточний обраний місяць).                                                                                                               |
| `OUTPUT_DIR`                                                                                     | Куди складається результат (`output`).                                                                                                                                                       |

## 🔹 generator_timesheet — структура

```
generator_timesheet/
├── resources/                                ⚠️ немає в git
│   ├── ОБЛІК.xlsx/
│   │   └── аркуш "Табель" — ПОСАДА, ЗВАННЯ, ПІБ, (необов.) ПІДРОЗДІЛ + одна колонка на кожен день місяця
│   ├── report/                               ← щоденні рапорти
│   │   └── DD.MM.YYYY - щоденний рапорт.docx ← дата зчитується з НАЗВИ файлу, не зі змісту
│   ├── information_unit/                     ← лише для режиму "ОБЛІК для виплат"
│   │   └── <файл підрозділу>.xlsx/
│   │       └── аркуш "ТАБЕЛЬ"/"Табель" — категорія виплати (число) чи статус (текст) на кожен день
│   └── data.json                             ← назва/скорочення власного підрозділу (щоб розпізнати підпис наприкінці рапорту)
└── output/                                   ← ⚠️ очищається перед кожним запуском
    ├── ОБЛІК.xlsx                            ← результат (той самий шлях для обох режимів)
    ├── Потребує_ручної_перевірки.txt         ← лише якщо є що зауважити
    └── error_mis_statuses.xlsx               ← лише для режиму виплат, лише якщо є розбіжності з information_unit/
```

▶️ Немає `resources/`? Створіть заготовку (кілька вигаданих рядків):

```bash
cd generator_timesheet && python resources_example/generate_sample.py
```

Створює `resources/ОБЛІК.xlsx` (аркуш `Табель`, лише базовий день заповнено). `resources/report/*.docx` і `resources/data.json` — окремо (вільний текст/зразок JSON вище в розділі проєкту).

#### 🔧 Основні змінні `constants.py`

| Змінна                                   | За що відповідає                                                                                            |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `DEFAULT_STATUS`                         | Статус за замовчуванням ("РВЗ" — у районі виконання завдань).                                               |
| `STATUS_HEADING_RULES`                   | Заголовок групи рапорту → новий статус (тут вчиться розпізнавати НОВІ формулювання заголовків).             |
| `STATUS_MEANINGS`                        | Довідник "скорочення статусу → повне пояснення" (лише для читання коду/файлу, на розпізнавання не впливає). |
| `STATUS_COLORS`                          | Колір заливки клітинки в `ОБЛІК.xlsx` для кожного статусу/категорії виплати.                                |
| `PAYMENT_STATUS_CONVERSIONS`             | Статус → фіксована категорія виплати (для режиму "ОБЛІК для виплат").                                       |
| `PAYMENT_STATUS_OVERRIDES`               | Коли файл `information_unit/` уточнює причину — яким значенням замінити базовий статус.                     |
| `PAYMENT_MISMATCH_COMPARABLE_STATUSES`   | Для яких статусів взагалі має сенс звіряти розбіжність із `information_unit/`.                              |
| `FREEFORM_STATUS_PATTERNS`               | Речення-винятки з розділу "Поза межами...", які все одно розпізнаються автоматично.                         |
| `SIGNATORY_UNIT_NAMES`                   | Назва/скорочення підрозділу — з `resources/data.json`, не хардкодиться тут.                                 |
| `PERSONEL_LIST_SHEET_NAME`, `OUTPUT_DIR` | Аркуш джерела ("Табель") і папка результату.                                                                |

4. **Номери БАТ/БЗ** — `Зчитати обрану папку з документами (для номерів БАТ / БЗ)?` (не з'явиться в режимах "тільки рапорт"). Так — вказуєте папку з готовими Word-документами, і скрипт сам знаходить у них номери. Ні — номери беруться такими, як уже вписані в `constants.py`.
5. **Поправки за минулий місяць** — `Чи потрібно вказувати в рапорті зміни до наказу за попередні місяці?` (лише для режимів "Все разом" / "Тільки рапорт на додаткову винагороду"; для режиму "поправки" це питання не задається — сам вибір режиму вже є згодою). Див. "Додаткові можливості" нижче.
6. Скрипт мовчки читає `ПРИДАНІ.xlsx`, `ОБЛІК.xlsx`. Якщо в `ОБЛІК.xlsx` не знайдеться людина на посаді "Командир батальйону" — зупиниться з поясненням.
7. **Населений пункт і координати КСП** (лише якщо генеруються БР) — `Введіть населений пункт КСП (формат: КИЇВ):` і `Введіть координати КСП (формат: 36T TT 12345 67890):`. Невірний формат — скрипт покаже помилку й попросить ввести ще раз.
8. **Відкрити результат** — `Відкрити папку output після завершення генерації?`

#### Результат

Папка `output` з підпапками `br`, `br_save`, `extractbr`, `logwar` та готовими рапортами `.docx`, або `output/RESULT_accounting.xlsx` для звірки обліку.

## 🔹 generator_timesheet

#### 📌 Опис

Проєкт формує табель обліку особового складу (`ОБЛІК.xlsx`, аркуш `Табель`) на основі щоденних рапортів про зміни (`.docx`): для кожного військовослужбовця перевіряє, чи повідомляє рапорт цього дня про зміну статусу — якщо так, записує нову подію (з датою, коли вона дійсно відбулась, а не датою самого рапорту — рапорт часто повідомляє про зміну "заднім числом"), якщо ні — просто продовжує попередній статус у колонку наступного дня. Є два режими генерації: звичайний табель зі статусами (`РВЗ`/`ВП`/`ШП`/...) і "ОБЛІК для виплат", де замість `РВЗ` підставляється категорія виплати (число), яку подають самі підрозділи.

---

#### Підготовка

🗂 Файлова структура — див. дерево на початку файлу (розділ "🔹 generator_timesheet — структура"). Коротко: `ОБЛІК.xlsx` і `data.json` — обов'язкові, `report/*.docx` — обов'язковий хоча б один (дата береться з НАЗВИ файлу), `information_unit/*.xlsx` — лише для режиму "ОБЛІК для виплат".

❗ Перед запуском переконайтесь, що `ОБЛІК.xlsx` не відкритий у Excel — інакше буде помилка.

---

#### Зразок `resources/data.json`

```json
{
  "unit": {
    "SHORT_UNIT_BATTALION": "0 бат",
    "SHORT_UNIT_BRIGADE": "00 обрбр",
    "FULL_UNIT_BUT": "0 батальйону морської піхоти",
    "FULL_MILITARY_UNIT": "військової частини А0000"
  }
}
```

Усі 4 ключі обов'язкові — саме ці варіанти написання скрипт шукає в тексті рапорту, щоб розпізнати рядок підпису. Сама лише згадка назви/скорочення частини підписом НЕ вважається (інакше законне речення про людину, яка згадує власну частину, хибно зникло б) — потрібне ще й слово ролі поруч ("командир"/"начальник штабу").

---

#### Статуси (значення в колонках дат)

| Статус       | Що означає                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| `РВЗ`        | У районі виконання завдань — за замовчуванням, зокрема одразу після повернення з будь-якої відсутності |
| `ВП`         | Відпустка                                                                                              |
| `ВПСЗ`       | Відпустка за станом здоров'я                                                                           |
| `ШП`         | Шпиталізація                                                                                           |
| `СЗЧ`        | Самовільне залишення частини                                                                           |
| `ВД`         | Відрядження                                                                                            |
| `ВЛК`        | На проходженні військово-лікарської комісії                                                            |
| `ППД`        | Пункт постійної дислокації                                                                             |
| `ПРВД`       | Переведено (в інший підрозділ/частину)                                                                 |
| `ЗВІЛЬНЕНИЙ` | Звільнення з військової служби                                                                         |

---

#### Запуск

```bash
cd generator_timesheet
python index.py
```

Питання `Що зробити?`:

| Варіант                                   | Що отримаєте                                                                                                                                                                     |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Файл обліку особового складу (ОБЛІК.xlsx) | Звичайний табель зі статусами.                                                                                                                                                   |
| Файл ОБЛІК для виплат з БЧС               | Той самий табель (той самий файл `output/ОБЛІК.xlsx`), але кожна клітинка зі статусом `РВЗ` замінена на категорію виплати з `information_unit/`, якщо там є однозначне значення. |

---

#### Результат

`output/ОБЛІК.xlsx` — в обох режимах той самий файл (два прогони завжди окремі, `output` очищається перед кожним). Поруч, лише якщо є що зауважити, — текстовий файл `Потребує_ручної_перевірки.txt` (чи, для режиму виплат, `Потребує_ручної_перевірки_виплати.txt`): список усього, що НЕ вдалось застосувати автоматично — невідомий підзаголовок пункту рапорту, ПІБ не знайдено в `ОБЛІК.xlsx`, дата з рапорту не збігається з жодною колонкою (типова причина — друкарська помилка), чи вільний текст розділу "Поза межами...", який не вдалось однозначно розпізнати. Кожен рядок пояснює причину і, де можливо, який статус чи ПІБ малися на увазі — переглядайте цей файл щоразу, коли він з'являється. Коли зауважень немає, файл узагалі не створюється.

Режим виплат додатково звіряє щойно згенерований файл із КОЖНИМ файлом `information_unit/` окремо і, лише якщо знайдено хоч одну розбіжність, записує `output/error_mis_statuses.xlsx`. Коли прогін ПОВНІСТЮ чистий (ні зауважень, ні розбіжностей), програма додатково запитує, чи записати щойно згенерований файл кудись іще — якщо так, відкриває діалог вибору папки (стартує з `generator_br_and_report_for_money/resources/`, сусідній проєкт цього ж репозиторію, але папку можна обрати будь-яку).

⚠️ Папка `output` **повністю очищається** перед кожним запуском — заберіть потрібні файли з попереднього запуску заздалегідь.

---

#### Типові помилки саме цього проєкту

- **"не знайдено аркуш ТАБЕЛЬ"** (файл з `information_unit/`) — у файлі підрозділу немає аркуша з такою назвою (без урахування регістру) або він у форматі `.xls`.
- **"з рапорту не знайдено в resources\ОБЛІК.xlsx"** — людину, згадану в рапорті, ще не додано до табеля (напр. новоприбулий з іншої частини) — додайте рядок вручну і запустіть ще раз.
- **"відсутня серед колонок-дат"** — дата в самому рапорті не відповідає жодному дню місяця (типово — переплутаний місяць чи рік) — перевірте текст рапорту.
- **"файл заблоковано іншою програмою"** — закрийте Word/Excel і спробуйте ще раз.

#### Підготовка

🗂 Файлова структура — див. дерево на початку файлу (розділ "🔹 final_combat_report — структура"). `resources/data.json` (з розділом `"unit"` усередині) і `resources/СПИСОК.xlsx` — обов'язкові (перевіряються ще до появи будь-якого питання, скрипт одразу впаде без них). Решта — опційні, але варто знати, що саме мовчки ламається без кожного з них:

| Чого немає | Що станеться (без помилки в консолі, якщо не вказано інше) |
| --- | --- |
| Розділів `location_command_post`/`paragraph_one`/`paragraph_two`/`paragraph_seven` у `data.json` | Розділи 1/2/7 звіту лишаться порожніми. |
| Розділу `"ambiguous_callsign_overrides"` у `data.json` | Двозначний позивний (той, що збігається одразу в кількох людей у `СПИСОК.xlsx`) мовчки прив'яжеться до ПЕРШОГО знайденого збігу — console покаже попередження `⚠️ УВАГА: Позивний '...' належить кільком людям...`, але генерацію не зупинить. |
| Розділу `"bk_synonym_crew_overrides"` у `data.json` | Якщо той самий неофіційний запис витрати БК однаково підходить під кілька позицій довідника `БК ВБАК.xlsx` — обирається та, у якої найбільший залишок, а не обов'язково та, яку реально використав саме цей екіпаж. |
| `БК ВБАК.xlsx` | Назви БК у звіті лишаться "як почув оператор" (без заміни на офіційну назву з довідника). |
| Учорашнього `Додаток №1 ПБД_... {DD.MM.YYYY}.docx` у `resources/` | Номер звіту скидається на 1, жовте підсвічування змін не працює, а **обидва розділи по втратах (5.1, 5.2) виходять зовсім порожніми**. |
| `signal_json/<канал>/data.json` для конкретного каналу | Той розділ звіту просто порожній, без помилки в консолі (найлегше пропустити — перевіряйте очима). |

❗ `ЗАДАЧІ.xlsm`, який теж може лежати у `resources/` (лишився з інших проєктів репозиторію) — цим проєктом **не використовується взагалі** (жоден `.py`-файл його не читає).

⚠️ **`resources/` не потрапляє в git** — це означає, що ніде, крім вашого комп'ютера, немає копії `data.json`, `СПИСОК.xlsx` і `БК ВБАК.xlsx`. Якщо диск вийде з ладу чи файл випадково видалиться — відновити не вийде. Раз на якийсь час (напр. раз на тиждень) скопіюйте всю папку `resources/` кудись окремо (флешка, хмара, інший диск) "про запас".

#### 📋 Зразок `resources/data.json`

`resources/data.json` — ОДИН файл, що містить одразу 2 різні за призначенням речі:

1. **Щоденний текст самого звіту** (розділи 1/2/7 — оцінка противника, положення військ, проблемні питання) — це те, що реально пишеться/оновлюється ВРУЧНУ щодня чи через кілька днів, коли міняється обстановка. Тут немає "зразка на копіювання" в сенсі готового тексту — вміст щоразу свій, реальний, бойовий.
2. **Розділи з довідковими даними** (`"unit"`, `"ambiguous_callsign_overrides"`, `"bk_synonym_crew_overrides"`) — це радше налаштування, які вносяться один раз (`"unit"`) або зрідка, коли трапляється конкретний виняток (двоє інших). Ось для НИХ і є повний, готовий до копіювання зразок нижче — зі вставленими прикладами замість реальних назв/позивних.

#### Запуск

```bash
cd final_combat_report
python index.py
```

1. **`Ви хочете використовувати актуальні дані з Signal? (Так/Ні)`** — "Так" запускає `sigexport`, який переекспортовує 5 чатів (UAV/діяльність/артилерія/обстріли/комісії) з локального встановленого Signal Desktop прямо в `signal_json/`, **перезаписуючи** те, що там було. Потрібні: змінна середовища `APPDATA`, розлочений Signal Desktop із чатами саме з такими назвами. Якщо експорт не вдався — скрипт лише покаже помилку в консолі й піде далі зі старими/відсутніми даними, не зупиняючись.
2. **Папка `output` повністю очищається** (спершу пробує через Word/COM закрити вже відкритий попередній файл, якщо він заблокований).
3. **Година початку доби** (`1`-`24`, за замовчуванням `18`) — з якої години по яку рахується "доба" звіту.
4. **Дата звіту** (`DD.MM.YYYY`, за замовчуванням сьогодні).
5. Далі без питань: читає й нормалізує повідомлення з усіх 5 каналів за обране 24-годинне вікно, підвантажує вчорашній звіт (якщо є), оновлює `БК ВБАК.xlsx`, будує всі 7 розділів і підпис, зберігає результат і сам відкриває його у Word.

#### Результат

`output/Додаток №1 ПБД_0 бат {DD.MM.YYYY}.docx` (за обрану дату) — один файл, автоматично відкривається у Word після генерації.

⚠️ Щоб завтрашній запуск підхопив накопичені підсумки й підсвічування змін — сьогоднішній файл з `output/` потрібно вручну скопіювати в `resources/` під тією ж назвою, до завтрашнього запуску.

#### Типові помилки саме цього проєкту

- **Скрипт падає ще до появи будь-якого питання** — не знайдено `resources/data.json` (без розділу `"unit"`) або `resources/СПИСОК.xlsx` (перевіряється при імпорті, ще до запуску `main()`). Помилка в консолі покаже точну назву файлу/ключа, якого бракує.
- **`FileNotFoundError`/`KeyError`, що згадує `unit.json`, `ambiguous_callsign_overrides.json` чи `bk_synonym_crew_overrides.json`** — це старі назви окремих файлів, які вже не використовуються (див. примітку в розділі "🔹 final_combat_report — структура" вище). Перенесіть їхній вміст у відповідні розділи `resources/data.json`.
- **"Некоректний ПІБ..." під час формування підпису** — ПІБ у колонці `P` файлу `СПИСОК.xlsx` не розбивається на 3 слова.
- **Розділ у звіті порожній, без жодної помилки в консолі** — просто перевірте, чи є `signal_json/<канал>/data.json` для цього каналу (легко пропустити, повідомлення лише в консолі).
- **`⚠️ УВАГА: ПІБ досі не знайдено`** — позивний зі Signal-повідомлення не знайдено в `СПИСОК.xlsx`; текст залишається з позивним замість ПІБ, генерація не зупиняється.
- **`⚠️ УВАГА: Позивний '...' належить кільком людям...`** — той самий позивний є одразу в кількох людей у `СПИСОК.xlsx`, і немає запису для цього екіпажу в розділі `"ambiguous_callsign_overrides"` файлу `data.json` — скрипт узяв ПЕРШОГО знайденого; звірте вручну і, якщо не той, додайте запис (див. розділ "Зразок resources/data.json" вище) і запустіть ще раз.
- **Назва боєприпасу в звіті виглядає "не тією", хоч офіційна назва в `БК ВБАК.xlsx` є** — той самий неформальний запис витрати однаково підходить під кілька позицій довідника, і без запису в розділі `"bk_synonym_crew_overrides"` скрипт обрав позицію з найбільшим залишком, а не обов'язково правильну для цього екіпажу — додайте запис (див. той самий розділ вище) і згенеруйте звіт ще раз.
- **Розділи 5.1/5.2 (втрати) зовсім порожні** — немає вчорашнього `Додаток №1 ПБД...docx` у `resources/` (див. таблицю вище).
- **`Невірний формат дати`** — дата звіту введена не у форматі `DD.MM.YYYY`.
- **Помилка при видаленні файлу в `output/`** — попередній результат відкритий у Word, а `pywin32` не встановлено чи Word не вдалось закрити автоматично — закрийте документ вручну.
- **"Ви хочете використовувати актуальні дані з Signal?" → обрали "Так", але дані не оновились** — Signal Desktop не встановлено/не залогінено на цьому комп'ютері, або назви чатів у Signal відрізняються від очікуваних (`Кречет 2.0`, `Діяльність`, `Basketball`, `Пейнтбол`, `КОМІСІЇ`). Скрипт покаже помилку в консолі, але продовжить роботу зі старими даними з `signal_json/` — перевірте дату останнього повідомлення в звіті, щоб зрозуміти, чи дані свіжі.
- **Excel-файл `БК ВБАК.xlsx` "зіпсувався"/цифри виглядають дивно** — цей файл скрипт сам дописує щодня (нова колонка "кількість за <дату>" зі щойно порахованим залишком) — не редагуйте вручну колонки з датами, які скрипт УЖЕ створив, лише найпершу (без дати, стартовий залишок).
